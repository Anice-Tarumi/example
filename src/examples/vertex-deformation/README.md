# Vertex Deformation

持っているジオメトリは **真っ直ぐな円筒 1 本だけ**。
曲がりも捻りも断面の歪みも、すべて頂点シェーダーで作る。

CPU 側は毎フレーム何も触らない。uniform を更新するだけ。

## メビウス変換

断面に、単位円板をそれ自身へ写す一次分数変換を掛ける。

```glsl
vec2 mobius(vec2 w, vec2 a) {
  return cdiv(w - a, vec2(1.0, 0.0) - cmul(vec2(a.x, -a.y), w));  // (w - a) / (1 - conj(a)w)
}
```

`|a| < 1` ならこれは単位円板の自己同型で、**円を円に写す**。
つまり断面の輪郭は円のままで、円周上の点の分布だけが偏る。

縞を u 座標に固定で貼っておくと、輪郭は変わらないのに模様だけが片側へ寄って流れる。
拡大縮小や単純な変位では出せない動き方になる。
`a` を時間で回すと、偏りの向きだけがぐるりと回る。

## 法線を作り直す

頂点を動かしたら、元の法線は使えない。歪めた面のライティングが破綻する。

位置を `surface(u, v)` という関数にまとめ、`u` と `v` を微小にずらした 2 点から
接ベクトルを 2 本作って外積を取る。

```glsl
vec3 p  = surface(uv.x, uv.y);
vec3 pu = surface(uv.x + du, uv.y) - p;
vec3 pv = surface(uv.x, uv.y + dv) - p;
vec3 n  = normalize(cross(pv, pu));
```

`surface()` を 3 回呼ぶが、頂点シェーダーなので画素数ではなく頂点数ぶんしか走らない。

## 進行方向の符号

進行座標は `travel = z - uTime * uSpeed`。

travel が一定の特徴（リング・曲がり・膨らみ）は `z = C + t * speed` に沿って動く。
カメラは +z にいて -z を向いているので、これで特徴が手前へ迫ってくる。

符号を `+` にすると特徴がカメラから遠ざかり、リングが外周から中心へ吸い込まれて
**後ろ向きに飛んでいる**見え方になる。カメラもジオメトリも動かしていないので、
前進しているように見えるかどうかはこの符号だけで決まる。

## 実装メモ

- **カメラ側では経路の曲がりを 0 に落とす。** ここを曲げるとカメラが管の外に出る。
  奥ほど強く曲げれば、覗いた先が曲がって見えるだけで済む。
- 面は `BackSide`。内側から見るので外向きの面は要らない。
  フラグメント側でも `dot(n, view) < 0` なら法線を反転して受ける。
- 頂点位置をシェーダーで作るので、`boundingSphere` は手で与えるか
  `frustumCulled={false}` にする。元の円筒の大きさで判定されると消える。
- カーソルは追従を効かせる。生の値だとトンネルが跳ねる。

## 操作

- カーソルを動かすと進行方向が曲がる
- `Variant` で トンネル / メビウス / 捻り / ワイヤーフレーム
