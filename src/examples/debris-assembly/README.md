# Debris Assembly

上から降ってきた破片が積み重なり、その山が絵になる。

## 逆再生は使わない

「完成状態から弾き飛ばして、それを逆から再生する」のが古典的な手だが、**物理として破綻する**。

重力は時間反転しても成立する（放物線を逆に辿っても放物線）。
だが**摩擦・反発係数 1 未満・減衰は散逸項**で、エネルギーを奪う操作。
逆に回すとエネルギーを生む。

- 静止していた瓦礫が理由もなく動き出す
- 接触していた破片が原因なく離れる
- 積み上がった山が下から崩れ上がる

人間はこれを一目で「逆再生だ」と見抜く。

## 代わりに着地点を絵から決める

順方向のシミュレーションだけで作る。

1. **絵の不透明な画素から着地スロットを撒く**
2. 各破片を**そのスロットの真上**から落とす
3. 衝突ありで積もらせる

真上から落ちるのでほぼスロットに着く。そのわずかなズレが、
印刷したような整い方ではなく「自然に積もった」見え方を作る。
色も同じスロットから引くので、破片が絵の色を運ぶ。

### スロットの撒き方

一様乱択だと粗密ができて、絵に穴と塊が出る。
**格子を切ってセルごとに 1 点だけ置く**（ジッタ格子）。
ブルーノイズほど厳密ではないが、抜けと固まりは目に見えて減る。

格子の細かさは有効画素の割合から決める。絵によって被覆率が違うので、
固定の格子だと枚数が合わない。

## 焼く

落下と堆積を全フレームぶん回して、位置と姿勢を Float テクスチャ 2 枚に詰める。
実行時は `(破片, フレーム)` で引くだけ。[`vertex-animation-texture`](../vertex-animation-texture/) と同じ再生機構。

**焼く方式だからこの演出ができる。** 1800 体の衝突を毎フレーム解くのは実行時には重いが、
焼く時なら一度で済む。衝突ソルバは [`src/shared/collideSpheres.js`](../../shared/collideSpheres.js) を
`vertex-animation-texture` と共有している。

## 調整で効いたところ

- **よく跳ねる・よく滑ると山が広がって絵がぼやける。** 反発係数と摩擦をどちらも小さく。
- **落下高さを下げる。** 高いほど着地時の運動量が大きく、横へ逃げる。
- **一斉に降らせない。** 降り始めをずらさないと「壁が落ちてくる」ように見える。
- **破片の大きさをスロットの間隔に合わせる。** 大きすぎると押し合って絵が膨らむ。

## 限界

- 絵は**上から見たときだけ**読める。真横からは平らな瓦礫にしか見えない。
- 細かい絵は潰れる。破片のグリッドがそのまま解像度になる。
- ベイクはメインスレッドで走る。枚数とフレーム数を上げると初回に数百ミリ秒止まる。
  実運用では Worker へ逃がすか、結果を書き出して配る。

## 操作

- クリックで頭から再生
- `Variant` で 標準 / 細粒 / 粗粒 / ゆっくり降る
