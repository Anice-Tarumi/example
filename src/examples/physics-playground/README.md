# Physics Playground

外部の物理エンジンを使わない剛体球ソルバ。1500 体のペア衝突を毎フレーム解く。

## なぜ全ペアを見ないか

1500 体の総当たりは 1,124,250 ペア／フレーム。これに 2〜3 サブステップが掛かる。
回らない。

そこで **一様グリッドのブロードフェーズ** を挟む。

1. 各球をセル番号へ変換する
2. 計数ソートでセルごとの区間を作る（`Map` もリストも生成しない）
3. 自分のセルと隣接 26 セルだけを走査する

セル幅を最大直径より大きく取れば、隣接 27 セルで衝突相手を漏れなく拾える。
実際に見るのは 1 体あたり数十ペアで、二桁以上減る。

計数ソートは `cellStart` にセルごとの開始位置を作り、`cursor` を進めながら
`sorted` へ添字を撒くだけ。フレーム内で配列を 1 つも確保しない。

さらに **中身のあるセルだけ** を `occupied` に覚えておく。
セル総数は 38³ = 54,872 あるので、全セルを舐めると走査だけで潰れる。
0 → 1 になった瞬間に記録すれば、重複なく集められる。

`Broadphase` variant で、その占有セルをワイヤーフレームで表示できる。
球の集まりに追従してセルが生き死にするのが見える。

## 衝突の解き方

1. めり込み量を質量比で分けて位置を押し戻す
2. 相対速度の法線成分に反発係数を掛けて撃力を与える
3. 離れていく方向（`rvn > 0`）なら何もしない

質量は半径の三乗。大きい球が小さい球を押しのける。

## 焼く例との対比

[`vertex-animation-texture`](../vertex-animation-texture/) は破砕を事前計算して
テクスチャに焼く。あちらは毎回同じ結果でよい場合の手法。

こちらは毎フレーム解くので、カーソルで触れば崩れ方が変わる。
junni (`next.junni.co.jp`) 冒頭のブロック壁が CANNON.js を使っているのも同じ理由で、
キャラの衝突位置によって崩れ方が変わるため事前ベイクができない。

## 実装メモ

- `dt` は 1/30 で頭打ちにする。タブ復帰で巨大な `dt` が来ると一気に破綻する。
- `vertexColors` は付けない。geometry の `color` 属性を要求されるが持っていないので
  (0,0,0) が乗って真っ黒になる。`instanceColor` だけで色は付く。
- 速度で色を変えている。衝突がどう伝わるかが目で追える。
- カーソルはカメラ方向に垂直な、原点を通る平面へ落とす。カメラを回しても手前に来る。

## 操作

- ドラッグでカメラ、カーソルを近づけると球を押しのける
- `Variant` で 周回 / 落下 / カーソル主体 / ブロードフェーズ表示 を切替
